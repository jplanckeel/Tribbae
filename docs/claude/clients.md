# Clients reference (web + Android)

Screen-level behavior, mockups followed, and where logic is duplicated between web and Android.

## Architecture

- **Web** (refonte « Le feu de camp », mobile-first): `src/lib/api.ts` is the single API layer (base `/v1`, relative — Vite proxy in dev, `API_URL=… npm run dev` to target another backend; same origin in prod). Types in `src/lib/types.ts`, design tokens in `src/index.css` (`@theme`), category/folder metadata in `src/lib/categories.ts`. `lib/data.tsx` (`useMyData`) caches the user's links/folders/children; `components/Composer.tsx` (`useComposer`) owns every create/edit sheet (add, idea form, folder form, AI). Routes in `App.tsx` (data router), screens in `pages/`. Lint (`npm run lint`) uses the strict React Hooks v7 rules: no synchronous setState in effects — mount sheets only when open instead of resetting them.
- **Android**: `composeApp/src/commonMain/kotlin/` — `data/` (models, `*Repository`, `ApiClient`/`AuthenticatedApiClient` over `HttpURLConnection`, `SessionManager`), `viewmodel/LinkViewModel.kt` (large, holds most app state as `StateFlow`), `ui/` (Compose screens). Navigation is state-based in `AppModern.kt`: tabs are composed on first visit and then kept alive but unplaced (`keptHidden`) while another tab or a pushed screen is shown, so returning is instant and keeps scroll — a tab's `LaunchedEffect(Unit)` therefore runs once, not on every visit (community ideas refresh via `refreshCommunityIfStale`, 5 min). The Explorer mosaic renders cards in batches of 24. Measure perf on a release build: debug Compose is ~2× slower. All repositories default to `data.Backend.url` (**production** `https://tribbae.fr`); a debug build can target a local backend with `./gradlew :composeApp:assembleDebug -Ptribbae.apiUrl=http://10.0.2.2:8080` (`BuildConfig.API_URL`, applied in `MainActivity`; cleartext is allowed for 10.0.2.2/localhost only). Offline-first: local creation then sync, backend is source of truth — except for what was changed on the device and not yet received: items created here keep a local id (`SyncIds.isLocal`) until the server gives them one, offline updates/deletes are queued in `PendingChanges` (persisted), `LinkViewModel.pushPending` sends all of it (children → folders → ideas → updates → deletes, under a lock) before every sync pull, and `SyncIds.merge` keeps those changes when the server lists replace the local ones (`SyncTest`). Every local change goes through it (`markLinkChanged` + `schedulePush`), never a direct API call. Play Store: `applicationId` is `fr.tribbae.app` (final, never change it); `versionCode` is computed from the release-please version in `composeApp/build.gradle.kts` (major·10000 + minor·100 + patch, so minor and patch stay under 100); `targetSdk` 36 (edge-to-edge and predictive back are already handled). Release builds go through R8 (`isMinifyEnabled` + `isShrinkResources`, app rules in `composeApp/proguard-rules.pro`; kotlinx.serialization ships its own): anything used by reflection needs a keep rule, and a release must be tried on a device before shipping. Each GitHub release carries `tribbae-<version>-mapping.txt.gz` to deobfuscate crash traces. Eve reminders use inexact alarms (`setAndAllowWhileIdle`): don't add `USE_EXACT_ALARM` / `SCHEDULE_EXACT_ALARM` back.

## Screens and shared logic

Idea age (`ageRange`) stays a string server-side but is entered with an age picker (bands = Explorer filter bands, shortcuts from the tribe's children ages, precise steppers by 6 months under 2 years) and always written in one canonical form (« 3–6 ans », « 18 mois – 3 ans », « 10 ans et + », « Tous âges »); parsing/formatting live in `frontend/src/lib/age.ts` and `composeApp/.../data/AgeRange.kt` (keep in sync; `AgeRangesTest` pins the cases). Legacy free-text values are still read.

Searching in Explorer also shows « Dans vos idées » above the community results (three rows, then « Voir tout »; own public ideas only appear there). Logic in `searchMine` (`lib/links.ts`) and `data/IdeaSearch.kt` (`links.test.ts` ↔ `IdeaSearchTest`, same cases).

Explorer default order « À la une » is a weighted shuffle reseeded every 6 h (`rotationScore`, FNV-1a + u^(1/weight), weight from likes and freshness), implemented identically in `frontend/src/lib/links.ts` and `ui/ExploreScreen.kt` — keep them in sync (`androidUnitTest/.../RotationScoreTest.kt` pins reference values from the web).

Folder customization (« Personnaliser » screen: cover illu/uni/tipis/pois/rayures/photo, 9 illustrated banners, description, key date + countdown, « Pour qui » children, view mode, sort, pinned) lives in `folder.proto` (`UpdateFolderRequest` uses `optional` fields + `set_child_ids` so older clients don't wipe them; `internal/folder/style.go` validates; key date/children/pinned are hidden from non-tribe viewers). Logic is duplicated in `frontend/src/lib/folderStyle.ts` and `composeApp/.../data/FolderStyle.kt` (auto illustration from name/date, countdown labels — `FolderStyleTest` pins the cases). Banner drawings are generated from the design mockup into `frontend/src/components/FolderBannerArt.tsx` and `composeApp/.../ui/campfire/FolderBannerShapes.kt` (pastel ones take the folder color's bg/mid); folder icon paths and the 9-color palette (bg/mid/ink) are duplicated in `lib/categories.ts` and `ui/campfire/FolderCover.kt` / `Campfire.kt` / `Theme.kt`.

Visibility status (design system « Visibility »): Privé (you and your tribe), Tribu (collaborators, or a folder owned outside the tribe), Communauté (public). An idea follows itself then its folder; in a public folder only the owner's ideas are exposed (`link.PublicFolderFilter`), so they show Communauté and another member's private idea shows Tribu. For a folder the client doesn't know, it uses the server's `publicViaFolder`. Logic in `lib/visibility.ts` and `data/Audience.kt` (`visibility.test.ts` ↔ `AudienceTest`, same cases); web `components/VisibilityBadge.tsx`, Android `VisibilityBadge`/`IdeaVisibility` in `ui/campfire/Campfire.kt` with `LocalAudiences`. Idea cards show the round badge unless Privé, folder cards also color their tab, the idea screen and pinned folders show the full badge. Colors: `--color-vis-*` tokens and `VisPublicBg`/`VisPublicInk`.

The Like is the only way to keep an idea: there is no favorite in the clients. `GET /v1/liked-links` (`ListLikedLinks`, latest like first, ≤ 300, hides ideas no longer visible) feeds the « J'aime » tab of Mes idées on both clients; Android keeps the last list in `LinkRepository.liked` for offline use, and liking offline shows an error. `link.MigrateFavorites` turns favorites into likes of the idea's author at startup, marking ideas with `favorite_migrated` so an unliked idea stays unliked, with the idea's `updated_at` as date; `favorite` and `/v1/links/{id}/favorite` stay for older app versions.

Screen transitions follow the « Transitions & navigation » mockup on both clients: opening an idea morphs its card into the detail (web: View Transitions via React Router `viewTransition`, names `idea-visual`/`idea-title`, `lib/transitions.ts` + `index.css`; the detail shows the cached/preview link instantly so the morph has a target. Android: `Screen.Detail.origin` from `CardOrigins` (recorded by `IdeaVisual`) + `heroFrom` in `AppModern.kt`, `LocalOpenProgress` delays the detail body; predictive back shrinks it to 92 %). Drilling (detail → folder « Rangée dans ») slides in from the right while the previous page recedes 30 % and dims, and the source idea is outlined in the folder. Tab changes fade in with a 26 px slide in the tab's direction. Durations/easings live in `ui/Transitions.kt` and `index.css`; keep them in sync.

« Ma tribu » follows the « Ma tribu v2 » mockup on both clients (web `pages/Tribe.tsx`, Android `ui/ProfileModernScreen.kt`): the tribe seated around the campfire (accounts then children, 5 seats max then « +N »), tabs « Le foyer » (tribe accounts, pending invitations with « Relancer » = re-invite, children cards → child sheet with birthday, their folders and « Des idées pour … » opening the AI) and « Le cercle » (folder collaborators grouped by person — owner-only on the backend, so only my folders are manageable — then my pending circle invitations), « Inviter autour du feu » (foyer = tribe email invitation, cercle = circle email invitation to chosen folders, or share a folder link); every pending invitation card (foyer and cercle) has « Relancer » and « Annuler » (with confirmation), « Notre année en idées ». Settings follow the « Ma tribu · Réglages regroupés » mockup: the gear opens one « Réglages » screen (web `components/SettingsView.tsx` at `/tribu?ouvrir=parametres`, alias `/reglages`; Android `ui/SettingsScreen.kt`) grouping the account card (owner badge), La tribu, Préférences (appearance; on Android a global reminders switch, `data.ReminderPrefs`, kept on the device — off cancels every alarm), Outils, Compte et données (« Mot de passe » sends the reset link to the account address) and Aide; the version comes from `package.json` (`__APP_VERSION__`) and `BuildConfig.VERSION_NAME`. Ring positions, circle grouping, year stats and per-child idea counts are duplicated in `lib/tribe.ts` and `data/TribePage.kt` (`TribePageTest`).

Adding an idea follows the « Ajouter une idée v2 » mockup on both clients: a multi-step sheet (start from the clipboard link / a link / writing / a photo / the AI → the link is read and its findings shown → « Où on la range ? » with 3 suggested folders and their reasons, a folder picker with search and inline creation, category, age bands, public toggle → « C'est rangé ! » celebration with the eve reminder). Web `components/AddFlow.tsx` (opened by `useComposer().openAdd`, « Plus de détails » falls back to `LinkFormSheet`), Android `ui/AddFlowScreen.kt`. Suggestions, « qui la verra » and age bands are duplicated in `lib/addFlow.ts` and `data/AddFlow.kt` (`AddFlowTest`). Photos (« Une photo », and « Mettre une photo » in the idea form) are uploaded to the backend: see Photos below.

Dates are picked with a wheel picker on both clients (no native date input, no Material 3 `DatePickerDialog`/`TimePicker`): web `components/WheelPicker.tsx` (`Wheel` columns in `scroll-snap`, keyboard arrows/Page/Home/End, `role="spinbutton"`; `DateSheet` + `DateField`), Android `ui/WheelPicker.kt` (`LazyColumn` + snap fling, haptic tick, TalkBack adjustable; `DateWheelSheet` in a `ModalBottomSheet`). Used for an idea's date and time (`event`: local time chosen, 00:00 = no time), a folder's key date (`key`: today onwards, midnight; `anniv`: any year) and a child's birth date (`birth`: up to today, local noon). Days per month, leap years, bounds (an already saved value outside them widens them), shortcuts (« Aujourd'hui », « Demain », « Ce week-end », « Dans un mois », one per day) and the timestamp conversions live in `lib/dateWheel.ts` and `data/DateWheel.kt` (`dateWheel.test.ts` ↔ `DateWheelTest`, same cases, Europe/Paris).

Shopping list (« Liste de courses », web `pages/Shopping.tsx` at `/courses`, Android `ui/ShoppingListScreen.kt`): the ingredients of the chosen recipes grouped by product with quantities added up (units converted within g and ml, spoons/pinches/sachets… added per unit, a line found in a single recipe kept as written), in `lib/shopping.ts` and `data/ShoppingList.kt` (`shopping.test.ts` ↔ `ShoppingListTest`, same cases). The selection (recipes + checked lines) stays on the device (web `localStorage` `tribbae.courses`, Android `LinkRepository.shopping` saved by `Storage`, remapped when a local recipe gets its server id); a checked line's key includes its quantity, so it unchecks when the quantity changes. « Préparer la liste de courses » on a recipe opens it with that recipe added (`/courses?recette=<id>`, `Screen.Shopping(recipeId)`). Only Recette ideas are offered: those with ingredients can be picked, those without are shown greyed with « Ajouter les ingrédients », which opens the idea form (`pickRecipes` in `lib/shopping.ts` ↔ `ShoppingList.pick`). The add flow shows an « Ingrédients » field for the Recette category on both clients.

Dark mode « La veillée » follows the « Mode sombre · palette veillée » mockup (in `Tribbae — Refonte UI.html`): a warm dark, no shadows, depth from lighter surfaces (page `#1C1411` → card `#282019` → sheet/nav `#33281F`) and thin borders; categories, folder colors and avatars get dark tints with light inks; terracotta and prune keep their color, links turn `#F0855E`; « soleil » discs become orange halos; photos at 90 % brightness. The preference (« Apparence » Jour / Soir / Auto in Ma tribu, default Auto = follow the device) is kept on the device. Web: `lib/theme.ts` + `public/theme.js` (applied before first paint, a separate file because the CSP forbids inline scripts) set `<html data-theme>`; `index.css` redefines the `@theme` tokens under `:root[data-theme="dark"]` (plus `card`, `link`, `on-solid`, `sky`, `ground`, `blush`, `peach` tokens; `.surface-raised` for sheets, `.nav-bar` for the bottom bar). Use tokens (`bg-card`, not `bg-white`; `var(--color-…)` in inline styles; folder and avatar colors are CSS variables in `lib/categories.ts`) so both themes work. Android: `ui.Appearance` (pref saved by `AndroidStorage`, system mode from `MainActivity`) and the palette in `ui/Theme.kt` are getters that pick the light or dark value (`CardColor`, `SheetColor`, `OnDark` for text on prune/terracotta, `OnSolid`, `PhotoVeil`, `SunDisc`, `SoleilPanel`, pastel pairs `BlueBg/BlueInk`…); use them instead of `Color.White` or literals.
