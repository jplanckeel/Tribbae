# Backend reference

Details behind the backend summary in `CLAUDE.md`. Read the section for the area you touch.

## Server, data and HTTP

- `cmd/server/main.go` wires everything: Mongo connect → `db.EnsureIndexes` → `auth.EnsureAdminAccount` → services → gRPC server on `GRPC_PORT` (9090) → grpc-gateway mux on `PORT` (8080) dialing back into the gRPC server.
- MongoDB 9 with the Go driver v2 (`go.mongodb.org/mongo-driver/v2`: `bson.ObjectID`, `mongo.Connect(opts)`, GridFS through `db.GridFSBucket`). Decode into typed structs; a sub-document decoded into `bson.M`/`any` comes back as `bson.D` unless the database is opened with `BSONOptions{DefaultDocumentM: true}` (done for the GDPR export, which is written as JSON). Indexes live in `internal/db/indexes.go` (`EnsureIndexes` at startup): every list query must be served by an index matching its filter **and** sort (check with `explain`); to replace an index, add the old name to `obsolete` there (create never drops). Every operation is bounded by `db.OperationTimeout` (client `Timeout`). Batch lookups of authors/counts (`LoadStats`, comment authors) with `$in` and a projection — never one query per item, never load `password`.
- Each domain in `internal/<domain>/` (auth, link, folder, child, follow, comment, admin, ai) has `service.go` (business logic + Mongo access via `bson.M`) and `handler.go` (gRPC server implementing the generated interface). Services receive their `*mongo.Collection`s from `main.go`.
- **API surface is defined in `backend/proto/tribbae/v1/*.proto`** with `google.api.http` annotations. Generated Go, gateway and OpenAPI code lives in `backend/gen/` and **is committed** (needed for the Docker build) — regenerate with `task backend:proto`, never hand-edit.
- Sessions are sliding: JWTs last 30 days and both clients trade theirs for a fresh one through `POST /v1/auth/refresh` at most once a day, at launch and when the app/tab comes back (web `renewSessionIfStale` in `lib/api.ts` + `shouldRenew` in `lib/session.ts`, called from `main.tsx`; Android `data/TokenRenewal.kt` + `LinkViewModel.renewSessionIfStale`, `TokenRenewalTest`). An account unused for 30 days has to sign in again.
- Auth: `internal/interceptor` is a gRPC unary interceptor that validates `Authorization: Bearer <JWT>` and puts the user ID in the context. Endpoints that work unauthenticated must be added to the `publicMethods` map there (token is then optional) — read endpoints for public content (`GetLink`, `GetFolder`, `ListLinks` with a folder, comments) are public and rely on the service-level visibility checks. Every `AdminService` method is admin-only: `UnaryAdminAuth` guards the whole service by prefix, so a new admin RPC needs nothing declared (`internal/admin/access_test.go` checks each method). Admin stats (`GetStats`, `GET /v1/admin/stats`, `internal/admin/stats.go`): new ideas (public/private), new accounts and active accounts per week or month, `$dateTrunc` in Europe/Paris (weeks start Monday; `time/tzdata` is embedded since the alpine image has no zoneinfo), empty periods filled with 0; web only (`components/AdminStats.tsx`, Recharts, lazy-loaded). Active = `users.last_seen_at`, set at register/login/token refresh at most once an hour (`auth.TouchLastSeen`); only the latest activity is kept, so past periods are underestimated.
- Some routes bypass grpc-gateway and are plain `net/http` handlers wrapped in `main.go`: `POST /v1/ai/generate` (`withAI`), `GET /v1/links/preview` (Open Graph extraction, `withPreview`), and the GDPR routes `GET /v1/account/export` / `POST /v1/account/delete` (`withAccount`, `internal/account`; deletion requires the password, is rate-limited like login, and erases everything the account owns while keeping other users' ideas — **a new collection holding user data must be added to `account.Service.Export` and `Delete`**). `auth.ValidateToken` rejects tokens of deleted accounts. Privacy policy `frontend/src/pages/Privacy.tsx` (`/confidentialite`), terms `pages/Terms.tsx` (`/cgu`, accepted at sign-up on both clients) and legal notice `pages/LegalNotice.tsx` (`/mentions-legales`) share the editor/host identity in `lib/legal.ts` — placeholders starting with « [à compléter » are highlighted until filled; the server renders all three (`seo/pages.go`, sitemap). both clients link them from Réglages (Confidentialité in « Compte et données », the other two in « Aide »); Android opens them in the browser. Android `LinkViewModel.signOut()` also wipes the offline cache. New non-proto HTTP routes follow the same wrapper pattern.
- Photos (`internal/photo`, `withPhotos`): `POST /v1/photos` (signed in, body = the raw image, ≤ 12 MB, own rate limit, outside the 1 MB `MaxBody`) decodes JPEG/PNG/WebP only, turns it upright (EXIF orientation), shrinks it to 1600 px and re-encodes it as JPEG (no metadata, so no GPS), stores it in MongoDB GridFS (bucket `photos`, owner in `metadata.owner_id`, file name = random 128-bit token) and answers `{url}` built from the request host (`https://tribbae.fr/v1/photos/<token>` in prod), which becomes the idea's `imageUrl`. `GET /v1/photos/<token>` is public and cached forever. `RunCleanup` deletes photos older than a day that no idea (`image_url`) or folder (`banner_url`) cites. Clients shrink before sending: web `lib/photo.ts` (`usePhotoUpload`) + `components/PhotoUpload.tsx`; Android `ImagePickerHelper` (copy in `filesDir/images`, upright, 1600 px) then `LinkViewModel.uploadLocalPhoto` when the idea is saved, and `uploadPendingPhotos` after each sync for ideas still holding a `file://` path (offline or created before uploads existed).
- The site lives on `https://tribbae.fr` (`SITE_URL`: canonical URLs, sitemap, email and folder-share links). `httpx.CanonicalHost` redirects everything requested on `REDIRECT_HOSTS` (old domain `tribbae.bananaops.cloud`, `www.tribbae.fr`) to it (301 for GET/HEAD, 308 otherwise), API included; Traefik routes all three names. The admin account email `tribbae@bananaops.cloud` is an account identifier and stays as is.
- In production a single image (root `Dockerfile`) serves the built frontend from `/public` (`STATIC_DIR` to override); anything under `/v1/` goes to the API. The SPA fallback goes through `internal/seo`: for each URL it replaces what lies between `<!--seo:head-->` markers in `frontend/index.html` with that page's head (title, description, canonical on `SITE_URL`, Open Graph, schema.org JSON-LD: Recipe/Event/Book/CollectionPage/FAQPage/BreadcrumbList) and fills `#root` with equivalent plain HTML, so search engines and AI crawlers that don't run JS see real content. Only anonymously visible content is rendered (same rules as a visitor without account); unknown/private ideas get 404 + noindex, private screens noindex, legacy URLs 301. It also serves dynamic `/sitemap.xml` (with images) and `/llms.txt`. The client mirrors head tags with `components/Seo.tsx` (every page renders one; it removes the server's `data-seo` tags on mount). The FAQ lives in `frontend/public/faq.json`, read by `pages/Faq.tsx`, the server (FAQPage) and the Android app (copied into its assets at build time by the `syncFaq` Gradle task, parsed by `data/Faq.kt`). Likewise the « À propos » page (`/a-propos`) lives in `frontend/public/about.json`, read by `pages/About.tsx` and the server (AboutPage, sitemap, llms.txt); Android opens it in the browser from the profile, like the privacy policy. Category intros are duplicated in `seo/categories.go` and `lib/categories.ts`.
- JSON is camelCase (protojson); enums serialize as names, e.g. `LINK_CATEGORY_RECETTE`.
- Emails (`internal/mail`): transactional emails go through the Brevo API (`BREVO_API_KEY`, `MAIL_FROM`, `MAIL_FROM_NAME`; without a key they are only logged). `mail.Mailer` renders French HTML + text bodies from `internal/mail/templates/` (embedded; table layout + inline styles following the « Emails Tribbae » mockup, since mail clients ignore flexbox/SVG; logo and icons are PNGs in `frontend/public/email/`, served from `SITE_URL/email`; user input escaped) and sends in the background — a failed email never fails the user action, and logs carry only the email type, never the address. Services get it through small `Notifier` interfaces + `SetNotifier` (auth: welcome, account: deletion confirmation, tribe: invitation, member removed by the owner and new owner when the creator leaves — never naming a deleted account; departure emails throttled in memory to one per recipient per day). Brevo is listed as a processor in `Privacy.tsx`.
- Link images: `internal/preview` scrapes pages (Chrome TLS fingerprint via `netsafe.NewBrowserClient`, then WhatsApp/Facebook preview UAs, oEmbed). `link.RunImageBackfill` (started in `main.go`) fills `image_url` for links without one in the background, recording attempts in `image_checked_at` (retry after 7 days); changing a link's URL triggers an immediate retry. Android mirrors the extractor offline in `androidMain/.../data/PageImageExtractor.kt` (jsoup) + `OgImageFetcher.kt`, and both clients fetch an image when an image-less idea is opened.

## AI generation (`internal/ai`)

Ideas are written by the **local Ollama model only, no web search** (`service.go`, `ollama.go`, `prompt.go`). The model answers under a JSON schema imposed via Ollama `format` (title, description, category, tags, ageRange — no URL nor price, they would be invented); `parseIdeas` normalizes and salvages truncated JSON. Small CPU VPS: default `qwen3:1.7b`, `think:false` only when the model supports thinking, one generation at a time → `ErrBusy`/429, pulled and warmed at startup. Ideas are only returned; clients save the ones the user keeps. Each idea carries a short `why` (« pourquoi », in the schema); `POST /v1/ai/generate` also takes optional `count` (≤ 8) and `exclude` (titles already proposed: listed in the prompt and filtered out), used to bring a new idea when the user drops one. `expectedCategory` takes the earliest hint word of the request.

Clients follow the « Idées avec l'IA v2 » mockup (web `components/AiSheet.tsx`, opened by `useComposer().openAi({ folderId?, prompt?, childId? })`; Android `ui/AiGenerateScreen.kt`, `Screen.Ai`): a sentence to complete (« Je cherche [des activités] pour [Léo] [ce week-end], [à la maison], budget [gratuit]. » + optional detail; children come from the tribe), inspirations that fill it in cascade, a glowing tipi with rolling messages while generating, 5 ideas arriving one by one with their « pourquoi », keep / drop (a dropped one is replaced: refill of 3 with `exclude`), then the kept ones fly into the folder (default: the origin folder, else an existing folder with the generated name, else a new one; the folder picker is shared with the add flow: `components/FolderPicker.tsx` / `FolderPickerSheet`). The sentence is sent as is as the prompt (children named with their age). Sentence options, inspirations and labels are duplicated in `lib/aiRequest.ts` and `data/AiRequest.kt` (`AiRequestTest`). Model benchmark on real prompts: `go test -tags aibench -run TestBench ./internal/ai` (see `bench_test.go`).

Config is all env vars, see `backend/internal/config/config.go` (Mongo, JWT, ports, Ollama, `ADMIN_PASSWORD`).
