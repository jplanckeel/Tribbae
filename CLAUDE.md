# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Tribbae is a family idea-management app (links, recipes, activities, gifts, events) with three parts that share one REST API:

| Part | Stack | Dir |
|------|-------|-----|
| Backend | Go + gRPC + grpc-gateway (REST) + MongoDB | `backend/` |
| Web | React 19 + TypeScript + Vite + Tailwind 4 | `frontend/` |
| Android | Kotlin Multiplatform + Jetpack Compose (application id `fr.tribbae.app`, code package `com.linkkeeper.app`) | `composeApp/` |
| AI | Ollama (local model, Docker) | `backend/internal/ai/` |

**Core rule (from `.kiro/steering/`): every user-facing feature must be implemented on both clients (web + Android).** Docs, comments and UI strings are in French; gRPC error messages are in English.

## Commands

Task runner is [Task](https://taskfile.dev) (`Taskfile.yml` at the root).

```bash
task dev                # Ollama (Docker) + backend + frontend in parallel
task dev:docker         # Everything via docker-compose.local.yml
task backend            # go run ./cmd/server — NOTE: loads backend/.env.example, not .env
task backend:proto      # buf generate (run after editing any .proto)
task frontend:dev       # Vite on :5173, proxies /v1 -> localhost:8080
task build              # Android debug APK (./gradlew :composeApp:assembleDebug)
task run                # install + launch on connected device
task check              # ./gradlew check (Android lint + tests)
task seed               # k6 run scripts/seed-data.js (test data)
```

Backend (from `backend/`):
```bash
go build ./...
go test ./...
go test ./internal/link -run TestName -v   # single test
```
Backend tests (`internal/{link,folder,follow,comment}/*_test.go`) hit a real MongoDB at `mongodb://localhost:27017`, create a throwaway `tribbae_test_<id>` DB, and **skip** (not fail) if Mongo isn't reachable. Some use `gopter` property-based testing.

Frontend (from `frontend/`): `npm run build` (runs `tsc -b` then `vite build` — this is the type check CI runs), `npm run lint`, `npm test` (Vitest, `src/lib/*.test.ts`, pure logic in Node with `TZ=Europe/Paris`; `npm run test:watch` while editing). Logic duplicated with Android is tested on both sides with the same cases (e.g. `age.test.ts` ↔ `AgeRangesTest`, `links.test.ts` ↔ `RotationScoreTest`): change a case on one side, change it on the other.

QA: the `qa` agent (`.claude/agents/qa.md`) runs every suite, starts the app locally (throwaway `tribbae_qa` database, no real email, never production) and checks the main flows plus the project's edge cases (tribe/circle rights, public vs private, unverified email, offline sync, dark mode, web/Android parity, GDPR), then reports bugs without changing app code. Use it to check a PR or before a release.

CI (`.github/workflows/test.yml`): `go build` + `go vet` + `go test -race` (with a MongoDB service) + `govulncheck` for backend, `npm ci && npm run lint && npm test && npm run build` for frontend, `./gradlew assembleDebug` for Android. `release.yml` triggers on `v*` tags (APK + Docker images).

## Git workflow

- **One PR per topic.** Never commit on `main`: branch from an up-to-date `main`, keep the branch to a single subject (a fix, a feature, a CI change…), and open a separate PR for anything unrelated found along the way. A CI fix and a dependency bump are two PRs, not one.
- Branch names: `<type>/<short-kebab-description>`, e.g. `fix/govulncheck-go-patch`, `feat/tribe-invitations`, `ci/mongo-9`.
- **Commits follow [Conventional Commits](https://www.conventionalcommits.org/)**: `<type>(<scope>): <description>`, description in English, imperative, lowercase, no final period.
  - Types: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `style`, `build`, `ci`, `chore`, `revert`.
  - Scopes (optional): `backend`, `frontend`, `android`, `ai`, `proto`, `seo`, `ci`, `docker`, `deps`, or a backend domain (`link`, `folder`, `tribe`…).
  - Breaking change: `!` after the type/scope and a `BREAKING CHANGE:` footer.
  - Examples: `fix(ci): always install the latest go 1.26 patch`, `feat(tribe)!: require confirmation before sharing content`.
- PRs are squash-merged, so **the PR title must itself be a Conventional Commit** (it becomes the commit on `main`). The PR description says what changed, why, and how it was tested.
- Commits must be authored and signed by the `jplanckeel` account (`Jérémy PLANCKEEL <jeremy.planckeel@outlook.com>`, GPG key `49D1339A1DA8FB47`), set in this repo's local git config. Never pass `--no-gpg-sign` or override the identity, never rewrite published history and never force-push `main`.
- **Every commit needs a DCO sign-off** (`Signed-off-by: Jérémy PLANCKEEL <jeremy.planckeel@outlook.com>`): the DCO app blocks any PR containing a commit without it. Always commit with `git commit -s` (a local `prepare-commit-msg` hook also adds it). GPG signing and sign-off are two different things; both are required.

## Backend architecture

- `cmd/server/main.go` wires everything: Mongo connect → `db.EnsureIndexes` → `auth.EnsureAdminAccount` → services → gRPC server on `GRPC_PORT` (9090) → grpc-gateway mux on `PORT` (8080) dialing back into the gRPC server.
- MongoDB 9 with the Go driver v2 (`go.mongodb.org/mongo-driver/v2`: `bson.ObjectID`, `mongo.Connect(opts)`, GridFS through `db.GridFSBucket`). Decode into typed structs; a sub-document decoded into `bson.M`/`any` comes back as `bson.D` unless the database is opened with `BSONOptions{DefaultDocumentM: true}` (done for the GDPR export, which is written as JSON). Indexes live in `internal/db/indexes.go` (`EnsureIndexes` at startup): every list query must be served by an index matching its filter **and** sort (check with `explain`); to replace an index, add the old name to `obsolete` there (create never drops). Every operation is bounded by `db.OperationTimeout` (client `Timeout`). Batch lookups of authors/counts (`LoadStats`, comment authors) with `$in` and a projection — never one query per item, never load `password`.
- Each domain in `internal/<domain>/` (auth, link, folder, child, follow, comment, admin, ai) has `service.go` (business logic + Mongo access via `bson.M`) and `handler.go` (gRPC server implementing the generated interface). Services receive their `*mongo.Collection`s from `main.go`.
- **API surface is defined in `backend/proto/tribbae/v1/*.proto`** with `google.api.http` annotations. Generated Go, gateway and OpenAPI code lives in `backend/gen/` and **is committed** (needed for the Docker build) — regenerate with `task backend:proto`, never hand-edit.
- Sessions are sliding: JWTs last 30 days and both clients trade theirs for a fresh one through `POST /v1/auth/refresh` at most once a day, at launch and when the app/tab comes back (web `renewSessionIfStale` in `lib/api.ts` + `shouldRenew` in `lib/session.ts`, called from `main.tsx`; Android `data/TokenRenewal.kt` + `LinkViewModel.renewSessionIfStale`, `TokenRenewalTest`). An account unused for 30 days has to sign in again.
- Auth: `internal/interceptor` is a gRPC unary interceptor that validates `Authorization: Bearer <JWT>` and puts the user ID in the context. Endpoints that work unauthenticated must be added to the `publicMethods` map there (token is then optional) — read endpoints for public content (`GetLink`, `GetFolder`, `ListLinks` with a folder, comments) are public and rely on the service-level visibility checks. Every `AdminService` method is admin-only: `UnaryAdminAuth` guards the whole service by prefix, so a new admin RPC needs nothing declared (`internal/admin/access_test.go` checks each method). Admin stats (`GetStats`, `GET /v1/admin/stats`, `internal/admin/stats.go`): new ideas (public/private), new accounts and active accounts per week or month, `$dateTrunc` in Europe/Paris (weeks start Monday; `time/tzdata` is embedded since the alpine image has no zoneinfo), empty periods filled with 0; web only (`components/AdminStats.tsx`, Recharts, lazy-loaded). Active = `users.last_seen_at`, set at register/login/token refresh at most once an hour (`auth.TouchLastSeen`); only the latest activity is kept, so past periods are underestimated.
- Some routes bypass grpc-gateway and are plain `net/http` handlers wrapped in `main.go`: `POST /v1/ai/generate` (`withAI`), `GET /v1/links/preview` (Open Graph extraction, `withPreview`), and the GDPR routes `GET /v1/account/export` / `POST /v1/account/delete` (`withAccount`, `internal/account`; deletion requires the password, is rate-limited like login, and erases everything the account owns while keeping other users' ideas — **a new collection holding user data must be added to `account.Service.Export` and `Delete`**). `auth.ValidateToken` rejects tokens of deleted accounts. Privacy policy: `frontend/src/pages/Privacy.tsx` (`/confidentialite`; editor and host placeholders to fill), linked from sign-up on both clients. Android `LinkViewModel.signOut()` also wipes the offline cache. New non-proto HTTP routes follow the same wrapper pattern.
- Photos (`internal/photo`, `withPhotos`): `POST /v1/photos` (signed in, body = the raw image, ≤ 12 MB, own rate limit, outside the 1 MB `MaxBody`) decodes JPEG/PNG/WebP only, turns it upright (EXIF orientation), shrinks it to 1600 px and re-encodes it as JPEG (no metadata, so no GPS), stores it in MongoDB GridFS (bucket `photos`, owner in `metadata.owner_id`, file name = random 128-bit token) and answers `{url}` built from the request host (`https://tribbae.fr/v1/photos/<token>` in prod), which becomes the idea's `imageUrl`. `GET /v1/photos/<token>` is public and cached forever. `RunCleanup` deletes photos older than a day that no idea (`image_url`) or folder (`banner_url`) cites. Clients shrink before sending: web `lib/photo.ts` (`usePhotoUpload`) + `components/PhotoUpload.tsx`; Android `ImagePickerHelper` (copy in `filesDir/images`, upright, 1600 px) then `LinkViewModel.uploadLocalPhoto` when the idea is saved, and `uploadPendingPhotos` after each sync for ideas still holding a `file://` path (offline or created before uploads existed).
- The site lives on `https://tribbae.fr` (`SITE_URL`: canonical URLs, sitemap, email and folder-share links). `httpx.CanonicalHost` redirects everything requested on `REDIRECT_HOSTS` (old domain `tribbae.bananaops.cloud`, `www.tribbae.fr`) to it (301 for GET/HEAD, 308 otherwise), API included; Traefik routes all three names. The admin account email `tribbae@bananaops.cloud` is an account identifier and stays as is.
- In production a single image (root `Dockerfile`) serves the built frontend from `/public` (`STATIC_DIR` to override); anything under `/v1/` goes to the API. The SPA fallback goes through `internal/seo`: for each URL it replaces what lies between `<!--seo:head-->` markers in `frontend/index.html` with that page's head (title, description, canonical on `SITE_URL`, Open Graph, schema.org JSON-LD: Recipe/Event/Book/CollectionPage/FAQPage/BreadcrumbList) and fills `#root` with equivalent plain HTML, so search engines and AI crawlers that don't run JS see real content. Only anonymously visible content is rendered (same rules as a visitor without account); unknown/private ideas get 404 + noindex, private screens noindex, legacy URLs 301. It also serves dynamic `/sitemap.xml` (with images) and `/llms.txt`. The client mirrors head tags with `components/Seo.tsx` (every page renders one; it removes the server's `data-seo` tags on mount). The FAQ lives in `frontend/public/faq.json`, read by both `pages/Faq.tsx` and the server (FAQPage). Likewise the « À propos » page (`/a-propos`) lives in `frontend/public/about.json`, read by `pages/About.tsx` and the server (AboutPage, sitemap, llms.txt); Android opens it in the browser from the profile, like the privacy policy. Category intros are duplicated in `seo/categories.go` and `lib/categories.ts`.
- JSON is camelCase (protojson); enums serialize as names, e.g. `LINK_CATEGORY_RECETTE`.
- Tribe (`internal/tribe`, `tribe.proto`): accounts of one family share everything (ideas, folders, children). `tribe.Service.Peers(userID)` = the user + members with `sharing=true`; it is injected via `SetTribePeers` into the link, folder and child services and every ownership check must go through it (`isPeer`/`ownedByTribe`), never `owner_id == userID` alone. Joining is by invitation only (`internal/tribe/invitations.go`, `tribe_invitations`): `AddTribeMember` emails `SITE_URL/invitation#<token>` (hashed token, 7 days, one per tribe and address, resend after 10 min, members + pending ≤ 12) and answers the same whether the address has an account or not; `AcceptTribeInvitation` requires the signed-in account to use the invited address (the link proves it receives that inbox), `GetTribeInvitation` is public. A new member sees the tribe immediately but their own content joins only after they confirm (`sharing`). Web `pages/Invitation.tsx` (token kept in sessionStorage while signing in), Android `ui/InvitationDialog.kt` + `MainActivity.extractInviteToken`. Publishing (idea or folder visibility, moving an idea into a public folder) stays author/owner-only. One tribe per account (unique index on `members.user_id`); without a tribe document the tribe is virtual and named after the account. Ideas are always signed with the author's account name; the tribe name is only for « La tribu … » (home, Ma tribu). Clients mirror the peer set (web `useMyData().peers`, Android `LinkViewModel.isTribePeer`).
- Email verification (`internal/auth/verify.go`, `email_verifications`: hashed token, 24 h, one per account, resend after 1 min): the welcome email carries `SITE_URL/verifier-email#<token>`; `POST /v1/auth/email/verify` is public (the link proves the inbox), `POST /v1/auth/email/resend` and `GET /v1/auth/me` (`emailVerified`, also in login/register/reset responses) need a session. A password reset or an accepted tribe invitation also verifies the address. Until verified (`users.email_verified_at`, existing accounts included, admin seeded verified) the server refuses with `FailedPrecondition` « email address not verified » to publish (idea or folder turning public, idea created in/moved into a public folder — already-public content stays editable), invite into the tribe and add a collaborator: `auth.RequireVerifiedEmail` is injected via `SetEmailCheck` (link, folder) and `SetEmailVerifier` (tribe). Web: session `emailVerified` refreshed by `refreshAccount` (launch + tab focus), `components/VerifyEmailBanner.tsx` in `AppLayout`, `pages/VerifyEmail.tsx`. Android: `SessionManager.emailVerified`, `LinkViewModel.emailVerified`/`refreshAccount` (resume), `ui/EmailVerification.kt` (banner on home, `VerifyEmailDialog` from `MainActivity.extractVerifyToken`, `PublishLockedNote` on the public toggles); the offline sync leaves a refused publication pending (`waitingForVerification`) instead of failing.
- Circle invitations (`internal/folder/invitations.go`, `folder_invitations`, `folder.proto` `…CircleInvitation`, routes `/v1/circle/invitations`): the owner invites an address (account or not, same answer either way) to some of their folders with a role; the email links to `SITE_URL/invitation-cercle#<token>` (hashed token, 7 days, one invitation per owner and address — inviting again adds the folders, a new email only after 10 min, ≤ 30 pending, inviting needs a verified address); `GetCircleInvitation` is public, `AcceptCircleInvitation` requires the invited address, adds the account as collaborator (role from the invitation) and verifies its address; deleting a folder removes it from invitations. Both clients now invite through it (`Tribe.tsx` `CircleInviteForm`, `ShareFolderSheet` on both, Android `LinkViewModel.inviteToCircle`); `AddCollaborator` is kept only for older app versions; it emails the added account (`mail.CollaboratorAdded`, link to `SITE_URL/dossiers/{id}`, throttled in memory to one per folder and 5 per recipient per day). Web `pages/CircleInvitation.tsx`, Android `ui/CircleInvitationDialog.kt` + `MainActivity.extractCircleToken`.
- Connected apps / OAuth 2.1 (`internal/oauth`, behind `MCP_ENABLED`, off by default: every route then answers 404, `/mcp` included): authorization server for the remote MCP server at `SITE_URL/mcp` (Claude custom connector). Metadata `/.well-known/oauth-authorization-server` (RFC 8414, no CIMD) and `/.well-known/oauth-protected-resource[/mcp]` (RFC 9728); `/oauth/register` (DCR, public clients only, redirect URIs must be in `OAUTH_REDIRECT_URIS` — exact match, no loopback; unused clients erased after a day), `/oauth/authorize` (PKCE S256 required, `resource` must be the MCP URL, RFC 8707) → web consent page `pages/ConnectApp.tsx` (`/connecter-application#<request>`, uses the app session; `POST /v1/oauth/consent[/info]`), `/oauth/token` (form body only; code single-use 60 s — a replayed code revokes the access; access token 15 min, refresh token rotated on each use, reusing an old one revokes the whole grant), `/oauth/revoke`. Tokens are opaque (`tbm_at_…`/`tbm_rt_…`), stored SHA-256-hashed in `oauth_tokens`, never logged; a grant (`oauth_grants`) lasts 90 days at most and dies with a password change (`auth.SessionValid`) or the account. App JWTs never work on `/mcp` and MCP tokens never work on the app API. Scopes: `links:read`, `links:write`, `folders:read` (`offline_access` accepted and ignored). Web only: the consent runs in the browser.
- MCP server (`internal/mcpserver`, `SITE_URL/mcp`, same `MCP_ENABLED` switch; doc in `docs/mcp.md`): official Go SDK (`modelcontextprotocol/go-sdk`), streamable HTTP, stateless, JSON responses. Guards in order: HTTPS (outside local), `Origin` absent or in `SITE_URL` + `MCP_ALLOWED_ORIGINS` (DNS rebinding), OAuth access token via `auth.RequireBearerToken` (401 points to the protected resource metadata), 60 calls/min per grant and 120 per user. Tools call `link.Service`/`folder.Service` directly (same rights as the app): `list_folders` (folders:read; `writable` = `CanEditFolder` and not public), `list_links` (links:read; only the account's folders, title/URL/category/date, ≤ 100), `create_link` (links:write; stricter validation than the app: https public URL only, enum category, ≤ 10 tags, plausible `event_date`, no image; always private, refused in public folders since that would publish it; `MCP_DAILY_CREATE_QUOTA` per account over 24 h, default 30). No update/delete/admin tool. Ideas get `created_via: "mcp"` + `oauth_client_id` (never changed by `Update`). Every call is logged in `mcp_audit` (user, client, grant, tool, outcome, date — no arguments, no token; 90-day TTL). Tool descriptions and errors are fixed English text, never user content.
- Connected apps screen (`connected_app.proto`, `ConnectedAppService`, `GET /v1/connected-apps`, `DELETE /v1/connected-apps/{id}?deleteIdeas=true`, handler `oauth.AppsHandler`, app session only, works even with `MCP_ENABLED` off): lists the account's grants (site, scopes, dates, number of ideas the app added) and revokes one, optionally deleting the ideas it added (`link.Service.DeleteCreatedByClient`, ideas first so a failure can be retried). Web `ConnectedAppsSheet` in `pages/Tribe.tsx` settings, Android `ui/ConnectedAppsSheet.kt` from the profile settings. `Link.created_via` is exposed in the API and shown as « Ajoutée par Claude » on the idea on both clients; scope labels and that label are duplicated in `lib/oauth.ts` and `data/ConnectedApps.kt` (`oauth.test.ts` ↔ `ConnectedAppsTest`).
- Gemini on Android (AppFunctions, Android 16+, on-device, no backend change): `androidMain/kotlin/GeminiFunctions.kt` exposes `listFolders`, `createIdea` (title, optional url/description/category/folderName/tags; an existing writable folder of that name or a new private one) and `createFolder` (returns the existing one of the same name). The AppFunctions KSP compiler generates `TribbaeAppFunctionService` (declared in the manifest, `BIND_APP_FUNCTION_SERVICE`) and `assets/tribbae_functions.xml`; KDocs are the agent-facing descriptions (fixed English). Same rules as MCP: always private, never in a public folder or one where the user is only a viewer, no update/delete; validation in `data/AssistantRequests.kt` (`AssistantRequestsTest`). Creations go through a process-wide `LinkViewModel` on the shared `data.AppGraph` repository (also used by `MainActivity`; the push lock lives in `LinkRepository` so both view models never send the same item twice): local first, then pushed like any change. `androidx.appfunctions` needs `compileSdk` 37 (targetSdk stays 36) and the Kotlin `moduleName` set to `composeApp` (the compiler builds class names from it). Try it on an Android 16+ device/emulator: `adb shell cmd app_function execute-app-function --package fr.tribbae.app --function com.linkkeeper.app.GeminiFunctions#createIdea --parameters '{"title":"…"}' --brief-yaml`.
- Emails (`internal/mail`): transactional emails go through the Brevo API (`BREVO_API_KEY`, `MAIL_FROM`, `MAIL_FROM_NAME`; without a key they are only logged). `mail.Mailer` renders French HTML + text bodies from `internal/mail/templates/` (embedded; table layout + inline styles following the « Emails Tribbae » mockup, since mail clients ignore flexbox/SVG; logo and icons are PNGs in `frontend/public/email/`, served from `SITE_URL/email`; user input escaped) and sends in the background — a failed email never fails the user action, and logs carry only the email type, never the address. Services get it through small `Notifier` interfaces + `SetNotifier` (auth: welcome, account: deletion confirmation, tribe: invitation, member removed by the owner and new owner when the creator leaves — never naming a deleted account; departure emails throttled in memory to one per recipient per day). Brevo is listed as a processor in `Privacy.tsx`.
- Link images: `internal/preview` scrapes pages (Chrome TLS fingerprint via `netsafe.NewBrowserClient`, then WhatsApp/Facebook preview UAs, oEmbed). `link.RunImageBackfill` (started in `main.go`) fills `image_url` for links without one in the background, recording attempts in `image_checked_at` (retry after 7 days); changing a link's URL triggers an immediate retry. Android mirrors the extractor offline in `androidMain/.../data/PageImageExtractor.kt` (jsoup) + `OgImageFetcher.kt`, and both clients fetch an image when an image-less idea is opened.

### AI generation (`internal/ai`)
Ideas are written by the **local Ollama model only, no web search** (`service.go`, `ollama.go`, `prompt.go`). The model answers under a JSON schema imposed via Ollama `format` (title, description, category, tags, ageRange — no URL nor price, they would be invented); `parseIdeas` normalizes and salvages truncated JSON. Small CPU VPS: default `qwen3:1.7b`, `think:false` only when the model supports thinking, one generation at a time → `ErrBusy`/429, pulled and warmed at startup. Ideas are only returned; clients save the ones the user keeps. Each idea carries a short `why` (« pourquoi », in the schema); `POST /v1/ai/generate` also takes optional `count` (≤ 8) and `exclude` (titles already proposed: listed in the prompt and filtered out), used to bring a new idea when the user drops one. `expectedCategory` takes the earliest hint word of the request.

Clients follow the « Idées avec l'IA v2 » mockup (web `components/AiSheet.tsx`, opened by `useComposer().openAi({ folderId?, prompt?, childId? })`; Android `ui/AiGenerateScreen.kt`, `Screen.Ai`): a sentence to complete (« Je cherche [des activités] pour [Léo] [ce week-end], [à la maison], budget [gratuit]. » + optional detail; children come from the tribe), inspirations that fill it in cascade, a glowing tipi with rolling messages while generating, 5 ideas arriving one by one with their « pourquoi », keep / drop (a dropped one is replaced: refill of 3 with `exclude`), then the kept ones fly into the folder (default: the origin folder, else an existing folder with the generated name, else a new one; the folder picker is shared with the add flow: `components/FolderPicker.tsx` / `FolderPickerSheet`). The sentence is sent as is as the prompt (children named with their age). Sentence options, inspirations and labels are duplicated in `lib/aiRequest.ts` and `data/AiRequest.kt` (`AiRequestTest`). Model benchmark on real prompts: `go test -tags aibench -run TestBench ./internal/ai` (see `bench_test.go`).

Config is all env vars, see `backend/internal/config/config.go` (Mongo, JWT, ports, Ollama, `ADMIN_PASSWORD`).

## Clients

- **Web** (refonte « Le feu de camp », mobile-first): `src/lib/api.ts` is the single API layer (base `/v1`, relative — Vite proxy in dev, `API_URL=… npm run dev` to target another backend; same origin in prod). Types in `src/lib/types.ts`, design tokens in `src/index.css` (`@theme`), category/folder metadata in `src/lib/categories.ts`. `lib/data.tsx` (`useMyData`) caches the user's links/folders/children; `components/Composer.tsx` (`useComposer`) owns every create/edit sheet (add, idea form, folder form, AI). Routes in `App.tsx` (data router), screens in `pages/`. Lint (`npm run lint`) uses the strict React Hooks v7 rules: no synchronous setState in effects — mount sheets only when open instead of resetting them.
- **Android**: `composeApp/src/commonMain/kotlin/` — `data/` (models, `*Repository`, `ApiClient`/`AuthenticatedApiClient` over `HttpURLConnection`, `SessionManager`), `viewmodel/LinkViewModel.kt` (large, holds most app state as `StateFlow`), `ui/` (Compose screens). Navigation is state-based in `AppModern.kt`: tabs are composed on first visit and then kept alive but unplaced (`keptHidden`) while another tab or a pushed screen is shown, so returning is instant and keeps scroll — a tab's `LaunchedEffect(Unit)` therefore runs once, not on every visit (community ideas refresh via `refreshCommunityIfStale`, 5 min). The Explorer mosaic renders cards in batches of 24. Measure perf on a release build: debug Compose is ~2× slower. All repositories default to `data.Backend.url` (**production** `https://tribbae.fr`); a debug build can target a local backend with `./gradlew :composeApp:assembleDebug -Ptribbae.apiUrl=http://10.0.2.2:8080` (`BuildConfig.API_URL`, applied in `MainActivity`; cleartext is allowed for 10.0.2.2/localhost only). Offline-first: local creation then sync, backend is source of truth — except for what was changed on the device and not yet received: items created here keep a local id (`SyncIds.isLocal`) until the server gives them one, offline updates/deletes are queued in `PendingChanges` (persisted), `LinkViewModel.pushPending` sends all of it (children → folders → ideas → updates → deletes, under a lock) before every sync pull, and `SyncIds.merge` keeps those changes when the server lists replace the local ones (`SyncTest`). Every local change goes through it (`markLinkChanged` + `schedulePush`), never a direct API call. Play Store: `applicationId` is `fr.tribbae.app` (final, never change it); `versionCode` is computed from the release-please version in `composeApp/build.gradle.kts` (major·10000 + minor·100 + patch, so minor and patch stay under 100); `targetSdk` 36 (edge-to-edge and predictive back are already handled). Release builds go through R8 (`isMinifyEnabled` + `isShrinkResources`, app rules in `composeApp/proguard-rules.pro`; kotlinx.serialization ships its own): anything used by reflection needs a keep rule, and a release must be tried on a device before shipping. Each GitHub release carries `tribbae-<version>-mapping.txt.gz` to deobfuscate crash traces. Eve reminders use inexact alarms (`setAndAllowWhileIdle`): don't add `USE_EXACT_ALARM` / `SCHEDULE_EXACT_ALARM` back.

Idea age (`ageRange`) stays a string server-side but is entered with an age picker (bands = Explorer filter bands, shortcuts from the tribe's children ages, precise steppers by 6 months under 2 years) and always written in one canonical form (« 3–6 ans », « 18 mois – 3 ans », « 10 ans et + », « Tous âges »); parsing/formatting live in `frontend/src/lib/age.ts` and `composeApp/.../data/AgeRange.kt` (keep in sync; `AgeRangesTest` pins the cases). Legacy free-text values are still read.

Explorer default order « À la une » is a weighted shuffle reseeded every 6 h (`rotationScore`, FNV-1a + u^(1/weight), weight from likes and freshness), implemented identically in `frontend/src/lib/links.ts` and `ui/ExploreScreen.kt` — keep them in sync (`androidUnitTest/.../RotationScoreTest.kt` pins reference values from the web).
